## New

- **Aztec nodes (first part).** A node with `type: aztec` is checked for its version (`aztec_getNodeInfo`, with `node_getNodeInfo` for nodes before v5) against the stable releases of aztec-labs-eng/aztec-node, where the node is released since v6, and for the published security advisories of aztec-packages, with the same rules as Ethereum clients. Findings name the affected packages, and a note points to missing node releases whose release notes mention "security". Aztec nodes get a table of their own (VERSION, ADVISORIES); Telegram notifications and metrics include them (`component="node"`, `client="aztec"`). The node's L1 is set with `l1` (an Ethereum node of the config) or `l1_url` (a provider endpoint); it is validated, but not used yet. See "Aztec nodes" in the README.

## Changes

- **Advisories without a released fix:** a medium or low advisory that affects the running version but has no released fix is now only a note, not yellow: there is no update to install. Critical and high advisories without a fix stay yellow, and advisories with a released fix are assessed as before. This also changes the assessment of Ethereum nodes: for example, a node that was yellow only because of a medium advisory without a fix is now green, with the advisory listed as a note and still counted in the ADVISORIES column and the `x3f_advisories` metric.
- **JSON-RPC errors with HTTP 400:** if an endpoint answers a JSON-RPC request with HTTP 400 and a JSON-RPC error object, the finding now shows that error (e.g. `JSON-RPC error -32601: …`) instead of only `unexpected HTTP status 400 Bad Request`. Aztec nodes answer errors this way; for Ethereum endpoints that do the same, only the message changes, not the status.

## Upgrade notes

- **The GitHub cache is fetched again once.** The cache now keeps the package names of advisories and, for releases, the link and whether the release notes mention "security". Data cached by v0.2.0 is fetched again on the first run, two extra requests per client.

## Known limitations

- **Aztec: version and advisories only.** Network, sync status and upgrade readiness of Aztec nodes are not checked yet.
- **Aztec: security releases without an advisory are not recognized as urgent.** aztec-node v6.1.0 is a security release without a published GitHub advisory; it counts like any other release (yellow within the grace period), with a note that its release notes mention "security".
- **Aztec: node releases before v6 are not in aztec-node.** For a node older than 6.0.0, "first newer release" is 6.0.0, not the real successor; the status is still right.
