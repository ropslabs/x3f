x3f v0.2.0 completes version 1 of the Ethereum node check. Besides client versions, sync status and fork readiness, x3f now checks the published security advisories of your clients, can tell you on Telegram when a node's status changes, and writes Prometheus metrics.

## New

- **Security advisories.** x3f reads the published GitHub security advisories of each client repository and checks your running version against them (new ADVISORIES column). Critical or high with a released fix: red, with no grace period. Medium, low, or no fix released yet: yellow. Findings name the most severe advisories with GHSA ID, CVE and title.
- **Ignore list.** `ignore_advisories` in x3f.yaml, globally or per node, with a required reason and an optional expiry date. Ignored advisories are still listed as a note.
- **Telegram notifications.** A message when a node's status changes, worse or back to good; a daily reminder while a node stays red; `min_level: crit` for red only. The bot token comes from `X3F_TELEGRAM_BOT_TOKEN`, never from the config. Check your setup with `-notify-test`; use `-no-notify` for manual runs.
- **Prometheus metrics.** `-metrics-file` writes a file for the node_exporter textfile collector: status per node and check, client versions, advisory counts, the next fork, and the time and success of the last run. The README has example alerting rules.

## Upgrade notes

- **The GitHub cache is fetched again once.** The cache format changed: release data cached by v0.1.0 is fetched again on the first run, one extra request per client.
- **Nodes may change color after the update.** An advisory can turn a node yellow or red right away; the 30-day grace period only applies to lagging behind a release. Read the findings; if an advisory does not apply to your setup, add it to `ignore_advisories` with a reason.
- **More GitHub requests:** two per client and hour instead of one (releases and advisories). Without `GITHUB_TOKEN`, GitHub allows 60 per hour.
- **Exit code 1** now also means that a Telegram message or the metrics file could not be written.
- **Proxies:** x3f uses `HTTPS_PROXY`, `HTTP_PROXY` and `NO_PROXY`. With an `http://` node URL behind `HTTP_PROXY`, the proxy sees the full URL, including an API key in it; use `NO_PROXY` or `https://`.

## Known limitations

- **No damping against flapping.** A node that is unreachable for a single run causes two Telegram messages: red, then back to good. With Prometheus, the `for:` clause of an alerting rule waits instead. Damping in x3f is planned.
- **"none known" does not mean "safe".** It only means that no advisory published on GitHub affects the running version. Several clients publish none there (as of November 2026: Reth, Nethermind, Ethrex, Prysm, Nimbus and Grandine); watch their release notes and security channels as well.
